# BOX WOODWORK — ניהול מפעל

שלד ראשוני של המערכת: Next.js 15 (App Router) + Supabase.
מה שקיים כאן זה הבסיס — התחברות, הרשאות, נתונים חיים, מסך עובד, מסך מפעל,
כרטיס פרויקט עם שני השערים של מקס.

## הפעלה ראשונה

1. **חבילות**
   ```bash
   npm install
   npm i @anthropic-ai/sdk      # לתרגום עברית ↔ רוסית
   ```

2. **סופאבייס**
   - צור פרויקט חדש, אזור Frankfurt.
   - SQL Editor → הדבק את `001_box_woodwork_schema_v3.sql` → Run.
   - Storage → צור שני buckets: `measurements` (תמונות מידות) ו-`plans` (תוכניות).
   - Authentication → Users → צור את ששת המשתמשים, ואז הרץ את שאילתות ה-INSERT
     שנמצאות בהערות בתחתית קובץ הסכימה, עם ה-uuid האמיתיים.

3. **משתני סביבה**
   ```bash
   cp .env.example .env.local
   ```
   ומלא את המפתחות מ-Project Settings → API.

4. **הרצה**
   ```bash
   npm run dev
   ```

## עקרונות שחשוב לא לשבור

- **השערים נאכפים בדאטהבייס, לא במסך.** יש טריגר `guard_gates` שזורק שגיאה
  אם מנסים להזיז שלב נעול. גם מי שיעקוף את הממשק ייחסם.
- **הרשאות החתימה יושבות על העובד** (`can_approve_plans`, `can_release`),
  לא בקוד. שינוי הרשאה זה עדכון שורה.
- **כל מעבר נרשם ב-`stage_events`.** אל תעדכן סטטוס בלי לרשום אירוע —
  זה גם מי-עשה-מה וגם הנתונים שיאפשרו AI בהמשך.
- **סיבת תקלה תמיד מקוטלגת** (`reason_code`) בנוסף לטקסט החופשי.
- **עובד רואה רק את השלבים שלו** — נאכף ב-RLS, לא בסינון בצד הלקוח.

## מה עוד לא נבנה

מסך "עובדים", מסך "הגדרות שיוך", טופס פרויקט חדש, העלאת תמונות מהמצלמה,
מציג התוכניות המאושרות, מסך התקלות הנפרד, ויומן הפעילות.
כל אלה קיימים כבר בפרוטוטייפ ה-HTML ומועברים לפי אותו דפוס.
